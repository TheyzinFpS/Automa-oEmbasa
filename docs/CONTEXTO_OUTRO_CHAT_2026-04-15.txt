CONTEXTO TECNICO - EMBASA SAP DESKTOP
Data: 2026-04-15

1. OBJETIVO DO PROJETO
- Aplicacao desktop em Python + pywebview para automacao SAP.
- Interface HTML/CSS/JS integrada ao backend Python.
- Exibir validacoes, logs visiveis e progresso em tempo real.
- Rodar em ambiente corporativo, com distribuicao pela pasta de rede do setor.

2. ESTADO ATUAL REAL DO PROJETO
- Build PyInstaller funcionando.
- Frontend funcional e integrado.
- Popup simples na abertura se nao existir sessao SAP pronta.
- CPF/CNPJ com formatacao visual no front e envio limpo ao SAP.
- Endereco do empreendimento integrado ao fluxo.
- Logs publicos reduzidos para o usuario final.
- Cache local de cliente existente.
- Mascara de documento em logs tecnicos.
- Fluxo integrado ate o re-salvamento da VF02.

3. ETAPAS SAP INTEGRADAS NO CODIGO ATUAL
- CONEXAO -> sessao SAP validada por scripting
- XD03 -> busca cliente
- VA01 -> cria pedido
- VF01 -> cria documento de faturamento
- VF02 -> captura doc_fat
- FB03 -> ajuste contabil
- VF02 -> re-salva faturamento

4. ETAPA AINDA PENDENTE PARA FECHAR O FLUXO
- F110 -> geracao do boleto ainda precisa consolidacao final e validacao real

5. NOVA MELHORIA IMPORTANTE FEITA NESTA ETAPA
- O progresso da aba de processos deixou de depender apenas de concluido/erro final.
- Agora cada transacao SAP envia progresso parcial durante a propria execucao.
- O front passou a usar etapas internas unicas:
  - `XD03`
  - `VA01`
  - `VF01`
  - `VF02_CAPTURA`
  - `FB03`
  - `VF02_RESALVAR`
  - `F110`
- A barra visual de cada etapa agora avanca por percentual conforme os marcos reais da funcao no SAP.
- A etapa seguinte so avanca quando a anterior conclui com sucesso.

6. RETOMADA APOS FALHA
- Foi criado checkpoint de retomada no controller.
- Quando uma etapa falha:
  - a etapa fica vermelha no front
  - os dados ja preenchidos permanecem na tela
  - os dados ja obtidos do SAP permanecem no resultado parcial
  - aparece uma caixa de retomada com o botao:
    `Continuar do ponto de parada`
- Depois de corrigir o problema no SAP, o operador pode continuar da etapa que falhou sem refazer o fluxo inteiro.
- Estado atual da retomada:
  - funciona dentro da sessao atual da interface
  - nao foi feita persistencia de checkpoint apos fechar o app

7. ARQUITETURA ATUAL
- `main.py`
  - ponto de entrada

  - cria janela pywebview
- `interface.py`
  - ponte entre frontend e backend
  - envia logs e progresso em tempo real para o JS
  - agora tambem repassa checkpoint de retomada
- `backend/controller.py`
  - orquestra o fluxo completo
  - agora entende `resume_checkpoint`
  - guarda contexto minimo:
    - `cliente`
    - `pedido`
    - `faturamento`
    - `doc_fat`
- `backend/sap_connection.py`
  - valida e conecta na sessao SAP pronta
- `backend/flows/`
  - implementacoes por transacao SAP
  - agora com progresso parcial por etapa
- `interface/app.js`
  - validacoes, UI, progresso visual, temas, logs e interacoes
  - agora com:
    - percentual por etapa

10. COMANDOS PARA RODAR EM DESENVOLVIMENTO
- Se PowerShell estiver liberado:
  - `powershell -ExecutionPolicy Bypass -File .\setup_env.ps1`
  - `.\.venv\Scripts\python.exe .\main.py`
- Se PowerShell estiver bloqueado:
  - `python -m venv .venv`
  - `.\.venv\Scripts\python.exe -m pip install --upgrade pip`
  - `.\.venv\Scripts\python.exe -m pip install -r requirements-unificado.txt`
  - `.\.venv\Scripts\python.exe .\main.py`

11. COMANDO PARA REBUILDAR O EXECUTAVEL SEM POWERSHELL
- `.\.venv\Scripts\python.exe -m PyInstaller --noconfirm --clean .\main.spec`

12. LOCALIZACOES IMPORTANTES EM EXECUCAO
- Runtime local: `%LOCALAPPDATA%\EMBASA`
- Config local opcional: `%LOCALAPPDATA%\EMBASA\embasa_settings.json`
- Cache local: `%LOCALAPPDATA%\EMBASA\cache\cliente_cache.json`
- Log tecnico: `%LOCALAPPDATA%\EMBASA\logs\processo_tecnico.log`

13. CONFIGURACAO DE DELAY PARA TESTES
- Arquivo: `%LOCALAPPDATA%\EMBASA\embasa_settings.json`
- Estrutura:
  {
    "automation": {
      "observation_delay_seconds": 1.0
    }
  }
- Isso desacelera os passos observaveis sem depender de editar varios `sleep`.
